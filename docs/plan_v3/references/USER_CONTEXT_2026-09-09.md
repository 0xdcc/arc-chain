## 4. 业务方向与用户偏好

### 4.1 已知方向，不等于本轮全做

用户关注 Robinhood/BSC/Arc 上的三角套利、价差机会和跟单研究，偏好单笔原子执行。本次“大框架”的具体第一优先策略、链范围、预算和性能目标仍需用户结合你的方案确定。

不要把以下业务混成一种模型：

- 同链原子闭环套利；
- 跨链资金调拨或跨链套利；
- 跟单持仓策略；
- 做市/LP 策略；
- 只读研究与监控。

尤其“多链支持”不等于“跨链单笔原子执行”。跨链桥、跨链裸敞口、合约开发/部署等新增范围，应单列可行性、依赖和授权，不暗中加入。

### 4.2 套利经济口径

用户偏好 WETH 或 USDG 本金闭环，零跨币裸敞口。闭环的资产标识、链、精度、起止余额、Gas 计价和残余 dust 处理需要规格化；不要把 WETH、原生币、USDG、USDC 视为可直接互换的同一种资产。

经济判断看真实净利，而非表面价差、手续费率或名义容量。规划需明确区分：

- 报价阶段的预估净利；
- 仿真阶段的预计资产变化；
- 回执及余额对账后的已实现净利。

报价若已经扣过 DEX 费，不能再重复扣费。Gas 必须按目标链实际付费资产和费用结构折算；失败交易、授权交易及其他成本如何入账，要明确政策。不要把模拟成功、广播成功当作成交盈利；原子交易回滚通常仍可能消耗链上 Gas。

QQ 套利机会推送的用户门槛是扣除 DEX 费及实时 Gas 后净利大于零。成交前只能标“预估”，无法保证成交后获利；成交战报必须依据真实对账。不要通过伪造确定性“真实利润”满足推送文案。

用户不接受仅凭费率上限等代理指标否决高费但净利为正的真机会。但这不允许绕过资金安全、滑点、数据有效性和权限约束。新增风控指标需说明具体风险、证据、误杀代价与审批需求，不能简单认为“更严格就更正确”。

### 4.3 探路者与连击

既有用户偏好：首笔探路者，容忍上限表述为“≤1U”，单发后挂起对账，确认盈利后才考虑全量连击。

待澄清：“≤1U”是损失预算、下单本金还是另有定义；“全量”指哪个获准资金池。未明确前不能据此配置执行参数。“全量”无论如何不自动取消单笔 500 USD 上限，也不等于允许并发广播。

计划需提出并经确认的状态流：候选机会、预检、仿真、授权、广播、待确认、对账、允许下一笔、暂停/人工介入。重点回答超时但交易可能已广播、nonce 冲突、重复任务、重组、失败回执、实际亏损时怎样避免重复花钱。

### 4.4 研究与数据

偏好使用 DefiLlama 等有明确口径的资料；成交量不能充当 TVL，TVL 也不能直接等同特定交易规模的可执行深度。

回测不能用分钟 K 线声称验证秒级执行效果。需说明时间精度、缺失样本、价格时点、未来数据泄漏、选择偏差、费用与滑点，以及失败交易成本。历史收益/胜率没有样本和复现证据时，不作为规划论据。

跟单、防骗、做市 Skill 中的策略门槛具有适用范围，不要直接移植为通用套利硬门禁。

### F. 风险和变更请求

集中列出约束冲突、资金风险、数据风险、运行依赖和待批准事项。改变业务预期、安全/权限边界或验收语义，必须请求用户批准；保全规格的技术性测试修订由主脑独立复核，不能仅靠断言文本没变来证明覆盖没变。

### G. 本地接手说明

告诉 Hermes：先核实哪些事实、哪些单可以直接在获准范围内推进、哪些必须等用户决定。阶段状态至少区分“待调查、待批准、施工中、待独立审查、验收通过、部署待授权、已部署并核验、阻断”。
