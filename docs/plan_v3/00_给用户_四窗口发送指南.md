# 给用户：四个窗口怎么开、文件怎么发

**你只需要做两轮发送：先给主脑1一个ZIP和一段话；主脑1准备好后，再给另外三个窗口各一段话。**
把ZIP作为附件上传给Hermes，不是只粘贴ChatGPT下载链接。
不用给每个窗口重复上传整个项目，不用手动分配48张工单，不用读代码或决定函数名。

已纳入你的补充：本地Robinhood继续加V3/V4池不会要求你同步GitHub或重做计划。只核对需要复用的代码，数据差异另记；Arc独立注册自己的池。

本版固定4个主脑，角色名为M1/M2/M3/M4；不再启动旧A0–A7窗口。目标仍是`/root/projects/crypto/arc-chain`。

## 4. 如果某个窗口说找不到文件

先让它报告实际host/当前project/instance与缺失路径，交给主脑1核对；不要同意它另建一个arc-chain来“补齐”。如果只是附件无法读取，给它对应角色MD＋01＋02＋03可以帮助只读理解，但**没有共享协调目录前不能并行写入**。

不共用同一主机/磁盘时本方案的共享协调前提不成立，需要M1明确远端/同步方案；不能假定发了同一个目录字符串就是同一份文件。

## 5. 运行中你看什么

你主要看主脑1的总进度，另外三个窗口处理自己组的开发/审查并写共享outbox。主脑1汇总“已完成什么、当前阻断、下一阶段能否进入”。不需要你手动复制别的窗口的代码或测试输出。

四个窗口建议先总计6个子代理（1/2/2/1），资源富余才扩，单窗最多4。48是细分任务数，不是同时启动数；没有依赖或文件边界的任务不能为凑并行度强开。

本地Hermes若没有持续队列/完成回调，一个窗口回复结束后不保证自动唤醒。它应落盘再说明挂起节点；需要继续时给相应窗口发：

```text

```
